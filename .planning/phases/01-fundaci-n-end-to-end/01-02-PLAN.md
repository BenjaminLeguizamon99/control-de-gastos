<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> Data API de Supabase (PostgREST) | Cualquiera con la publishable key (publica) puede pegarle |
| internet -> /auth/v1/signup | Alta de cuentas sin autenticacion |
| maquina local -> Supabase Postgres | Conexion con credenciales de owner (postgres) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Information Disclosure | /rest/v1/probes, /rest/v1/alembic_version | mitigate | RLS sin policies + sin grants; curl de verificacion con PASS = 42501 o []; prohibido agregar GRANT |
| T-01-11 | Elevation of Privilege | /auth/v1/signup | mitigate | Toggle "Allow new users to sign up" off + curl que exige signup_disabled; allowlist del backend como segunda capa |
| T-01-12 | Spoofing | Firma de JWT | mitigate | Signing key ECC P-256 vigente, verificado via JWKS no vacio |
| T-01-13 | Information Disclosure | backend/.env (password DB) | mitigate | Lo crea el usuario, gitignored, el executor no lo imprime ni lo commitea; password alfanumerica sin pegarla en el chat |
| T-01-14 | Information Disclosure | recovery por email | accept | Supabase limita a 2 mails/h y OTP cada 60 s; SMTP propio fuera de alcance |
| T-01-15 | Tampering | conexion a DB | mitigate | `sslmode=require` en DATABASE_URL del pooler |
</threat_model>
