# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Alcance:** contrato provisorio y mínimo. Phase 2 define la identidad visual real (skill `frontend-design`, `DESIGN.md`, `tokens.css`) y reestiliza estas pantallas. Acá solo se fija lo necesario para que login, recuperación y logout sean usables, accesibles y consistentes en el celular (CONTEXT.md, Claude's Discretion: "mínima y funcional, sin invertir en estilos").

**Pantallas de la fase (y ninguna más):**
1. `/login` — Iniciar sesión (email + contraseña) + link "Olvidé mi contraseña".
2. `/recuperar` — paso 1: pedir código (email). Paso 2: código de 6 dígitos + contraseña nueva. Mismo componente, el paso es estado local.
3. `/` — Pantalla autenticada de prueba: muestra el email de la sesión y el `user_id` devuelto por `/me`.
4. Layout autenticado: header con el botón "Cerrar sesión", envuelve toda ruta protegida (AUTH-03: logout desde cualquier pantalla).

Sin pantalla de registro (D-06). Sin componentes de dominio.

## Layout

- Mobile first. Contenedor de formulario: ancho completo con padding horizontal 16px; `max-width: 384px` (`max-w-sm`) centrado en tablet/desktop.
- Altura: `min-h-dvh` (no `100vh`, por la barra de iOS). Padding inferior respeta `env(safe-area-inset-bottom)`.
- Formularios en una columna: label arriba del input, gap 8px label-input, 16px entre campos, 24px antes del botón principal.
- Botón principal: ancho completo, altura mínima 44px.
- Header del layout autenticado: alto 56px, padding horizontal 16px; nombre "Control de Gastos" a la izquierda, "Cerrar sesión" a la derecha.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white) | Fondo de página |
| Secondary (30%) | `#F4F4F5` (zinc-100) / borde `#D4D4D8` (zinc-300) | Header, borde de inputs |
| Text | `#18181B` (zinc-900) / secundario `#52525B` (zinc-600) | Texto principal / ayudas |
| Accent (10%) | `#2563EB` (blue-600) | Ver lista abajo |
| Destructive | `#DC2626` (red-600) | Solo mensajes de error de formulario y borde de input inválido |

Accent reserved for: (1) fondo del botón principal de cada formulario, (2) el link "Olvidé mi contraseña" y "Volver a iniciar sesión", (3) el anillo de foco (`focus-visible:ring-2`) de inputs y botones. Nada más.

"Cerrar sesión" es botón secundario: texto zinc-900, borde zinc-300, sin fondo de acento.

Modo oscuro: fuera de alcance (Phase 2).

## Interaction & States

| Elemento | Contrato |
|----------|----------|
| Login inputs | Email: `type="email"`, `autocomplete="username"`, `inputmode="email"`, `autocapitalize="none"`. Contraseña: `type="password"`, `autocomplete="current-password"`. |
| Código OTP | Un solo input: `inputmode="numeric"`, `autocomplete="one-time-code"`, `pattern="[0-9]{6}"`, `maxlength="6"`. No 6 cajitas separadas. |
| Contraseña nueva | `type="password"`, `autocomplete="new-password"`, mínimo 8 caracteres (validar en cliente con zod; Supabase valida igual). Un solo campo, sin "repetir contraseña". |
| Envío | Al enviar: botón `disabled` + texto de carga; inputs quedan editables. Enter envía el formulario. |
| Errores | Debajo del campo (validación) o arriba del botón (error del servidor), `role="alert"`, rojo destructive. Input inválido con `aria-invalid="true"` y borde rojo. |
| Foco | Autofocus en el primer campo de cada paso. Foco visible siempre (anillo de acento). |
| Sesión inicial | Mientras supabase-js resuelve la sesión al abrir: pantalla en blanco con "Cargando…" centrado (evita el parpadeo del login). |
| Redirecciones | Sin sesión en ruta protegida → `/login`. Con sesión en `/login` o `/recuperar` → `/`. Tras cambiar contraseña con éxito → `/` (la sesión de recovery ya queda activa). |
| Logout | Un toque, sin confirmación (no destruye datos; volver a entrar es trivial). Limpia la cache de TanStack Query y redirige a `/login`. |
| `/me` | Cargando: "Cargando…". Error: mensaje de error de red con botón "Reintentar". |

| Element | Copy |
|---------|------|

| Título recuperación | Recuperar contraseña |
| Paso 1 ayuda | Te mandamos un código de 6 dígitos a tu email. |

| Paso 2 ayuda | Revisá tu email e ingresá el código que te llegó. |
| Labels paso 2 | Código · Contraseña nueva |
| Paso 2 CTA | Cambiar contraseña (cargando: "Guardando…") |
| Reenviar | Reenviar código (link secundario en paso 2) |
| Volver | Volver a iniciar sesión |
| Header | Control de Gastos · botón "Cerrar sesión" |
| Pantalla autenticada | Título "Sesión iniciada"; cuerpo "Entraste como {email}." y "ID de usuario: {user_id}" |
| Empty state heading | no aplica (no hay listas en esta fase) |
| Empty state body | no aplica |
| Error: credenciales | Email o contraseña incorrectos. Revisalos e intentá de nuevo. |
| Error: código | El código es incorrecto o venció. Pedí uno nuevo con "Reenviar código". |
| Error: demasiados intentos | Demasiados intentos. Esperá unos minutos y volvé a probar. |
| Error: red / backend | No pudimos conectar con el servidor. Revisá tu conexión y tocá "Reintentar". |
| Error: no autorizado (401/403 de `/me`) | Tu cuenta no tiene acceso. Cerrá sesión e ingresá con otra. |
| Validación email | Ingresá un email válido. |
| Validación código | El código tiene 6 dígitos. |
| Validación contraseña nueva | Usá al menos 8 caracteres. |
| Destructive confirmation | ninguna — la fase no tiene acciones destructivas (logout no pide confirmación, ver Interaction) |

Paso 1 siempre avanza al paso 2 aunque el email no exista (no revelar qué emails tienen cuenta).
